# 决策系统思维导图

```
决策系统 (CmdDecisionTree)
│
├─ 输入数据 (CmdTreeInput)
│  ├─ current_robot_quantity: 当前机器人数量 (1-3)
│  ├─ blood_warn_state: 血量状态 (0-100)
│  ├─ game_process: 比赛状态 (4=进行中)
│  ├─ current_state_left_time: 剩余时间(秒)
│  ├─ is_success_ourpreempt: 我方占点 (0/1)
│  ├─ is_success_enemypreempt: 敌方占点 (0/1)
│  └─ is_ALL_state_level: 战力评估 (-1/0/1)
│
├─ 话题通信
│  ├─ [订阅] setcmdtree (std_msgs/String)
│  │  └─ 接收外部命令参数
│  │     └─ 格式: "quantity:3,blood:85,game:4,time:120,our:1,enemy:0,level:0"
│  │
│  └─ [发布] 两个话题
│     ├─ cmdtreeautoaim (std_msgs/String)
│     │  └─ 火力决策结果 (1=防御模式, 2=进攻模式)
│     │
│     └─ /cmdtree/navigation (std_msgs/UInt8)
│        └─ 导航命令 (0-4)
│
├─ 决策流程
│  │
│  ├─ 1. 比赛状态判断
│  │  └─ game_process == 4? → 进入决策树
│  │                        → 否则输出"比赛未进行"
│  │
│  ├─ 2. 机器人状态等级评估 (RobotstatelevelDecision)
│  │  │
│  │  ├─ 输入: 机器人数量 + 血量
│  │  │
│  │  ├─ 评级逻辑
│  │  │  ├─ 数量=3 && 血量>90 → 等级1 (最优)
│  │  │  ├─ 数量=3 && 血量>75 → 等级2
│  │  │  ├─ 数量=3           → 等级3
│  │  │  ├─ 数量=2 && 血量>75 → 等级4
│  │  │  ├─ 数量=2           → 等级5
│  │  │  ├─ 数量=1           → 等级6 (最劣)
│  │  │  └─ 其他             → 等级0
│  │  │
│  │  └─ 战力修正: level += is_ALL_state_level (限制1-6范围)
│  │
│  ├─ 3. 火力决策 (FireDecision)
│  │  │
│  │  ├─ 输入: 敌方占点状态
│  │  │
│  │  └─ 输出
│  │     ├─ 敌方占点? → 1 (防御fire模式)即攻击对方英雄为优先
│  │     └─ 否则     → 2 (进攻fire模式)即攻击对方步兵为优先
│  │
│  └─ 4. 导航命令决策 (分三档策略)
│     │
│     ├─ 时间判断
│     │  ├─ 剩余时间 ≤ 60秒 → "最后60秒"
│     │  └─ 剩余时间 > 60秒 → "前期阶段"
│     │
│     ├─ 【优势状态】等级1-2: PreemptSituation_3 (激进策略)
│     │  │
│     │  ├─ 敌方占点?
│     │  │  ├─ 是
│     │  │  │  ├─ 血量 < 40  → 0 (回出生点)
│     │  │  │  └─ 血量 ≥ 100 → 2 (2点巡航/辅助游击)
│     │  │  │
│     │  │  └─ 否
│     │  │     ├─ 血量 < 40  → 0 (回出生点)
│     │  │     └─ 血量 ≥ 100
│     │  │        ├─ 我方占点? → 4 (激进fire模式)
│     │  │        └─ 否       → 3 (尝试占点)
│     │  │
│     │  └─ 导航命令映射
│     │     ├─ 0: 回出生点
│     │     ├─ 1: 1点巡航
│     │     ├─ 2: 2点巡航/辅助游击
│     │     ├─ 3: 尝试占点
│     │     └─ 4: 激进fire模式
│     │
│     ├─ 【中等状态】等级3-4: PreemptSituation_2 (平衡策略)
│     │  │
│     │  ├─ 敌方占点?
│     │  │  ├─ 是
│     │  │  │  ├─ 血量 < 40  → 0 (回出生点)
│     │  │  │  └─ 血量 ≥ 100 → 2 (2点巡航/辅助游击)
│     │  │  │
│     │  │  └─ 否
│     │  │     ├─ 血量 < 40  → 0 (回出生点)
│     │  │     └─ 血量 ≥ 100
│     │  │        ├─ 我方占点? → 2 (2点巡航/辅助游击)
│     │  │        └─ 否       → 3 (尝试占点)
│     │  │
│     │  └─ 注: 中等状态下优先保持阵型,不做激进fire
│     │
│     └─ 【劣势状态】等级5-6: PreemptSituation_1 (保守策略)
│        │
│        ├─ 敌方占点?
│        │  ├─ 是
│        │  │  ├─ 血量 < 20  → 0 (回出生点)
│        │  │  ├─ 血量 > 75  → 2 (2点巡航/辅助游击)
│        │  │  ├─ 血量 > 40  → 1 (1点巡航)
│        │  │  └─ 其他       → 0 (回出生点)
│        │  │
│        │  └─ 否
│        │     ├─ 血量 < 20  → 0 (回出生点)
│        │     ├─ 血量 > 75
│        │     │  ├─ 我方占点? → 2 (2点巡航/辅助游击)
│        │     │  └─ 否       → 3 (尝试占点)
│        │     ├─ 血量 > 40  → 1 (1点巡航)
│        │     └─ 其他       → 0 (回出生点)
│        │
│        └─ 注: 劣势状态下降低风险,血量阈值更严格
│
└─ 输出数据 (CmdTreeOutput)
   ├─ robot_state_level: 机器人状态等级 (1-6)
   ├─ vision_nav_cmd: 导航命令 (0-4)
   ├─ fire_decision: 火力决策 (1-2)
   └─ description: 决策描述字符串
      └─ 格式: "[阶段]-[状态]([策略]):[命令描述]"
         └─ 示例: "前期阶段-优势状态(激进):尝试占点"
```

## 血量阈值常量

| 常量名称              | 数值 | 说明         |
|-----------------------|------|--------------|
| ROBOT_BLOOD_FULL      | 100  | 满血阈值     |
| ROBOT_BLOOD_PERFECT   | 90   | 完美血量阈值 |
| ROBOT_BLOOD_HIGH      | 75   | 高血量阈值   |
| ROBOT_BLOOD_LOW       | 40   | 低血量阈值   |
| ROBOT_BLOOD_DANGER    | 20   | 危险血量阈值 |

## 三档决策策略对比

| 状态等级 | 策略类型 | 血量阈值严格度 | 占点倾向 | 是否启用激进fire |
|----------|----------|----------------|----------|------------------|
| 1-2      | 激进     | 宽松 (40/100)  | 高       | 是               |
| 3-4      | 平衡     | 中等 (40/100)  | 中       | 否               |
| 5-6      | 保守     | 严格 (20/75)   | 低       | 否               |

## 决策逻辑关键点

1. **状态评估优先**: 先根据数量+血量确定基础等级,再用战力评估修正
2. **时间敏感**: 最后60秒阶段会影响决策描述(但当前逻辑中策略相同)
3. **占点优先级**: 敌方占点时倾向防守,我方占点且优势时才激进进攻
4. **血量为核心**: 所有三档策略的分支判断都依赖血量阈值
5. **话题解耦**: 火力决策和导航命令分别发布到不同话题,方便下游模块独立订阅

## 话题关系关键点

1. **单输入双输出架构**: 一个输入话题(`setcmdtree`)对应两个功能独立的输出话题
2. **决策解耦**: 火力决策和导航决策通过不同话题分发,下游模块可独立订阅所需内容
3. **数据类型差异**: 火力决策用String便于扩展,导航命令用UInt8节省带宽
4. **同步发布**: 两个输出话题在同一回调中发布,保证决策时刻的一致性
5. **命名空间策略**: 导航话题用绝对路径便于全局访问,火力话题用相对路径保持模块内聚
